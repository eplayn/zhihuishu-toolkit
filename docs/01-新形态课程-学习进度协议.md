## 二、加密方案（已完全破解）

### 2.1 两层结构

```
① 密钥获取（每次会话，按 module 索引）
   labc(module) -> GET appcomm-user.../c/has?secretStr=<RSA({module:N})>
                -> 响应 rt.sl = RSA 签名(signed) 的 JSON
                -> 用固定公钥"解密"（模幂）得到:
                   {"cKey":"<AES密钥>","ckv":1,"key":"<辅助密钥>",
                    "module":N,"nkv":2,"osVersion":3}

② 报文加密
   aesUtil.encrypt(json, cKey)
     = AES-128-CBC / Pkcs7 / IV = "1g3qqdh4jvbskb9x"
   body = {"secretStr": <base64>, "date": <epoch_ms>}
```

### 2.2 RSA 细节

```javascript
FIXED_PUB = "MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQCgfZmpLpPEpEFRKBe+ZjWJUjPe
              +7qg7pGqcfN3j2egJ8H2mrKwaEqZEnPnpi2O3hN8HRyaFozDOp8gwZiYfiI
              ZjWy0Jr/FNAiiKYh5bq0GsEn+ieMmRyJg/+i1rqizhvCXvFdrdGhFTw5EBwT
              psGdwe1utdlrvIJUAFWj9Yh4qbQIDAQAB"
```

- **1024 位，e = 65537**
- 请求方向：`RSA_encrypt(payload, FIXED_PUB)` —— 服务端用私钥解密
- 响应方向：服务端**用私钥加密**（签名），客户端**用公钥解密**：
  ```python
  m = pow(bytes_to_long(sl), e, n)     # 用 e 而不是 d！
  # 结果符合 PKCS#1 v1.5 填充: 00 01 FF...FF 00 <JSON>
  ```

## 四、学习与上报机制

### 4.1 三个上报接口

**`studyRecord/study`** —— 每 **2 秒**心跳：
```json
{"courseId":"20000001","resourceId":"70000003",
 "knowledgeId":"70000002","source":1,"studyFileType":2,
 "dateFormate":1791625741000}
```

**`studyRecord/report`** —— 每 **1 分钟**：
```json
{"courseId":"20000001","classId":"300001","fileId":94681025,
 "studyTotalTime":10,          // 本次学习秒数（每次 +10）
 "lastWatchTime":79,           // 播放位置（79 → 89 → 99，每次 +10）
 "knowledgeId":"70000002","shareCourseId":"",
 "watchUId":1,"nodeType":0,"dateFormate":1791625760000}
```

**`studyRecord/completed`** —— 标记资源完成：
```json
{"courseId":"...","knowledgeId":"...","classId":"...",
 "resourcesUid":"70000003","watchUId":1,"dateFormate":...}
```

### 4.2 学习单元的层级

```
课程 (courseId / mapUid)
  └─ 知识节点 (knowledgeId)          ← maptree 节点
       └─ 资源 (resourceId / resourcesUid)
            ├─ 视频 (fileId, nodeType=0)
            ├─ PPT  (get-ppt-page / get-ppt-detail-v2)
            └─ 测验 (questions-paper / query-knowledge-free-exam)
```

**"完成" 的判定**：调用 `studyRecord/completed` 传入 `resourcesUid`。

## 六、工具与方法沉淀

### 6.1 反混淆（自研）

`tools/deobf2.py` —— 针对 obfuscator.io **自定义 base64 字母表**变体：

```python
CUSTOM = 'abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789+/='
# ① base64 用自定义字母表解码
# ② UTF-8 解码
# ③ 数组旋转量用自保护校验和反推
```

**本次结果**：
- 文件 `base2.zhihuishu.com/js/2.js`（162 KB）
- 偏移 `0x1d4`，数组 623 元素
- **旋转量 = 394**（4 个语义锚点一致）
- 还原 512 处

### 6.2 抓包（绕过反调试）

**F12 和 CDP 都会触发反调试导致页面不渲染。**

替代方案：**mitmproxy 代理**

```powershell
# 1) 启动代理
mitmdump.exe -s capture_addon.py -p 8080

# 2) 计算 mitmproxy CA 的 SPKI 指纹，精准豁免（不动系统信任区）
#    4SxSxSsjPl/mN9Pk+HcCDPzIr8vw04JHMALRpgcHnUw=
chrome.exe --proxy-server=127.0.0.1:8080 `
           --ignore-certificate-errors-spki-list=<SPKI>
```

**关键点**：只用 SPKI 豁免比 `--ignore-certificate-errors` 精准，
且**不修改系统证书库**。
